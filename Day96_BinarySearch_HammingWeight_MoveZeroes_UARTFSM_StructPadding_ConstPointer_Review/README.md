## 💻 一、 今日白板程式題（系統廠高頻 3 題全數通過）

### 1. 二分搜尋法 (Binary Search - LeetCode #704) -> [`p1.c`](./p1.c)
- **難度標籤**：🟢 系統廠白板手寫必備 | **複雜度**：時間 $O(\log N)$，空間 $O(1)$
- **防禦性設計亮點**：
  - 空指標檢查 `if (nums == NULL)` 與空陣列檢查 `if (numsSize == 0)`。
  - **防止整數溢位**：使用 `mid = left + (right - left) / 2`，避免 `(left + right) / 2` 在大數相加時發生 Signed Overflow。
- **盲點檢討**：
  - 升序陣列中，當 `nums[mid] < target` 時，代表目標值較大，目標在右半區間，應向右收縮左邊界：`left = mid + 1`；反之當 `nums[mid] > target` 時才收縮右邊界：`right = mid - 1`。

### 2. 位元 1 的個數 / 漢明重量 (Number of 1 Bits - LeetCode #191) -> [`p2.c`](./p2.c)
- **難度標籤**：🟢 系統廠韌體位元運算必備 | **複雜度**：時間 $O(k)$，空間 $O(1)$
- **核心演算法（Brian Kernighan's Algorithm）**：
  - 核心語句：`n = n & (n - 1); count++;`
  - 物理機制：每次運算精準消除二進位中最右側（最低位）的 `1`。
  - 效能優勢：迴圈次數僅取決於「有幾個 1」，例如 $n = 128$（二進位 `10000000`）僅需跑 1 次迴圈，大幅超越跑滿 32 次的死板位移法！

### 3. 移動零 (Move Zeroes - LeetCode #283) -> [`p3.c`](./p3.c)
- **難度標籤**：🟢 陣列原地雙指針高頻題 | **複雜度**：時間 $O(N)$，空間 $O(1)$
- **核心思維**：
  - 第一階段：`fast` 指針遍歷陣列，遇到非零元素即原地覆寫到 `slow` 指針位置，保持非零元素的相對順序。
  - 第二階段：將 `slow` 之後至陣列結尾的所有位置補 `0`。
  - 零失誤通過空陣列、全零陣列與無零陣列等所有極限測資。

## 🚗 二、 自走車專案實務科普（系統廠面試官最愛問的通訊與時序痛點）

### 1. 跨板 UART 串口通訊——黏包（Packet Sticking）與撕裂解決方案
- **問題本質**：UART 在硬體層面僅是連續的「位元組流（Byte Stream）」，沒有天然的封包邊界。當上位機（樹莓派 ROS 2）高頻發送指令或通訊受雜訊干擾時，極易出現封包撕裂或黏包。
- **自訂二進位幀協議（Binary Frame Protocol）**：
  - **`0xAA 0x55` 雙位元組幀頭**：建立狀態機同步對齊點，未接收到完整幀頭前主動過濾雜訊。
  - **`Length` 長度欄位**：嚴格限定讀取長度，解決多包連續到達時的黏包問題。
  - **`Checksum` 校驗碼**：馬達火花雜訊導致校驗失敗時立即整包丟棄，絕不執行錯誤動作。
  - **接收端 FSM 狀態機解析器**：採用逐位元組狀態機（IDLE -> HEADER1 -> HEADER2 -> LEN -> PAYLOAD -> CHECKSUM），配合 Ring Buffer，實現零阻塞流暢通訊。

### 2. 感測器阻塞陷阱——超音波 `pulseIn()` 30ms 翻車致命傷
- **問題分析**：官方 `pulseIn()` 為純軟體死等（Busy-waiting）迴圈。前方無障礙物時會卡死 CPU 達預設逾時（約 30ms），造成紅外線循跡盲跑翻車。
- **優化方案**：
  - 軟體層面改用非阻塞定時狀態機。
  - 硬體層面改用微控制器的 **Timer 輸入捕獲（Input Capture）** 或外部中斷，由硬體計數器在 Echo 上下緣自動記錄脈衝寬度，**達到 0% CPU 佔用**。

## 🎙️ 三、 0x10 嵌入式 C 語言底層核心考題 -> [`0x10.c`](./0x10.c)

### 題 1：結構體記憶體對齊（Struct Memory Alignment）與 Padding 計算
```c
typedef struct {
    char a;   // 1 Byte  + 3 Bytes Padding
    int b;    // 4 Bytes
    short c;  // 2 Bytes + 2 Bytes Tail Padding
} StructA;   // 總計: 1 + 3 + 4 + 2 + 2 = 12 Bytes

typedef struct {
    int b;    // 4 Bytes
    short c;  // 2 Bytes
    char a;   // 1 Byte  + 1 Byte Tail Padding
} StructB;   // 總計: 4 + 2 + 1 + 1 = 8 Bytes
```
- **核心規律**：各欄位位址必須是對齊數量的整數倍，結構體總大小必須為最大對齊成員（4 Bytes）的整數倍。
- **韌體優化價值**：將成員變數按型態大小由大至小重新排列，能消除內部間隙，在此例中直接省下 **33%** 的記憶體空間（12 Bytes -> 8 Bytes）。

### 題 2：指標常數與常數指標（Const Pointer Rules）
- **`const int *p1`**：指向常數的指標（Pointer to Const Int）。所指向的值不能透過 `*p1` 修改，但指標本身所存的位址可以更改。
- **`int * const p2`**：常數指標（Const Pointer to Int）。指標本身是唯讀常數（位址不可改），但指向的記憶體內容可以被修改。
- **`const int * const p3`**：雙重鎖死。位址與內容皆為常數，不可更動。
- **秒殺心法（從右向左讀取法則，Right-to-Left Rule）**：從變數名出發，依序向左解析各修飾詞。
