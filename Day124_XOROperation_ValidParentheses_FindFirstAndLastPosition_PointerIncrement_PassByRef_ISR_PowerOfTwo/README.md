## 🎯 Part 2 面試陷阱題解析

### Trap 1: 複合運算子與自增順序（HackMD 考古第 6 題補充題）
```c
int a[] = {1, 2, 3, 4, 5, 6};
int *p = a;
*(p++) += 100;
*(++p) += 100;
```
1. `*(p++) += 100;`：後置 `++` 先以原指標（`&a[0]`）運算，`a[0]` 加上 100 變成 `101`，執行完畢後 `p` 指向 `a[1]`。
2. `*(++p) += 100;`：前置 `++` 先將指標由 `a[1]` 推進至 `a[2]`，再解引用加 100，`a[2]` 變成 `103`，此時 `p` 指向 `a[2]`。
3. 輸出結果：`101 2 103 4 5 6`。

### Trap 2: 傳值 (Call-by-Value) 與傳引用/指標（HackMD 筆試第 3 題原題）
```cpp
void change(int *a, int &b, int c) {
    c = *a;
    b = 3;
    *a = 2;
}
```
1. 輸出結果：`2 3 3`。
2. `c` 依然為 3 的原因：C/C++ 傳值呼叫時在 Stack Frame 複製參數，函式結束該區域變數銷毀，呼叫端的 `c` 絲毫不受影響。
3. 純 C 語言改寫：宣告為指標 `void change(int *a, int *b, int c)`，函式內以 `*b = 3` 修改，呼叫端傳入位址 `change(&a, &b, c)`。

## 🧠 Part 3 基本 0x10 韌體與作業系統觀念題

### Q1: 中斷常式（ISR）vs 一般函式（Function Call）
1. **觸發來源與硬體自動壓棧**：
   * Function Call 由軟體指令主動呼叫（如 `BL`），依編譯器呼叫慣例保存暫存器。
   * ISR 由硬體事件非同步觸發。ARM Cortex-M 硬體在觸發瞬間**自動將 8 個核心暫存器（xPSR, PC, LR, R12, R3, R2, R1, R0）壓入 Stack**，零軟體延遲。
2. **設計禁忌**：
   * **無參數與回傳值**：由硬體中斷向量表跳轉，無呼叫者可傳遞或接收值。
   * **禁止 Sleep / Block**：ISR 沒有所屬的 TCB，不參與作業系統睡眠排程。若在中斷中等鎖（Mutex）或延遲（Delay），會凍結整個 CPU 中斷優先級，引發系統死鎖崩潰。

### Q2: 判定 2 的冪次方（Power of 2）的兩種 Bitwise 神技
1. **硬體位元數學原理**：
   * 寫法 A：`x & (x - 1)` $\to$ **消除二進位最低位的 1**。若為 2 的冪次方（二進位只有唯一一個 1），消掉後必為 0。
   * 寫法 B：`x & (~x + 1)` 即 `x & (-x)` $\to$ **提取二進位最低位的 1（LSB）**。若二進位只有唯一一個 1，提取出的就是它自己（等於 x）。
2. **`x > 0` 強制防禦邊界的重要性**：
   * **$x = 0$**：不是 2 的次方，但 $0 \ \& \ (-1) = 0$，不防禦會誤判為真。
   * **$x = \text{INT\_MIN} (-2147483648)$**：二進位為 `0x80000000`（僅最高符號位為 1）。若未加 `x > 0`，減 1 或取負號引發有號整數溢位（Undefined Behavior），甚至誤判為 2 的次方。

## 🚗 自走車專案實務科普：雙核心 UART 封包黏包、同步字元與 FSM 狀態機

### 1. 學生專案的 UART 災難：字串流「黏包、斷包與移位」
* **情境**：
  樹莓派（ROS 2）與 Arduino / STM32 透過 UART 傳遞速度控制命令。
  若直接傳送字串或生位元組，由於馬達啟動時的電磁干擾（EMI）或兩端啟動時間不一致，接收端可能從資料流的「中間」開始讀取。
* **致命後果**：
  位元組錯位！例如速度值 `100` 被誤解析為角度 `0`，馬達瞬間失控打轉！

### 2. 工業級解法：固定格式 ＋ 雙同步字元 (Header) ＋ 狀態機 (FSM)
* **封包規格設計**：
  `[0xAA] [0x55] [Msg_ID (1B)] [Length (1B)] [Payload (N Bytes)] [CRC8 (1B)]`
  * 採用雙同步字元 `0xAA 0x55`（二進位交替 `10101010 01010101`），抗噪能力極強。
* **有限狀態機（FSM）接收解析流程**：
  ```
  [WAIT_HEADER1] ── 收到 0xAA ──> [WAIT_HEADER2] ── 收到 0x55 ──> [WAIT_LEN] ──> [WAIT_PAYLOAD] ──> [CHECK_CRC]
        ^                              │ (若非 0x55 則重置)
        └──────────────────────────────┘
  ```
* **面試加分亮點**：
  * **自同步能力（Self-Resynchronization）**：即使傳輸線被拔掉再插上、或中間掉包，狀態機在下次掃描到 `0xAA 0x55` 時能**單週期自我校正同步**，系統永不當機。
