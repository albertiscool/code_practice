# Day 52: HackMD 韌體工程師 0x10 面試聖經 Part 1 (16-bit 秒數溢位防禦、標準 MIN 巨集與 #error 指令)

今天是對照 HackMD 經典文章《韌體工程師的 0x10 個問題》的特訓第一階段，我們精準複習了預處理指令常數與 16-bit 整數溢位防禦、標準 `MIN` 巨集括號防護與 `*p++` 副作用 (Side Effects) 陷阱，以及 `#error` 於編譯階段的配置阻斷檢查。

## 📝 實戰考題與詳細解答 (HackMD 0x10 Questions 1~3)

### HackMD 第 1 題【預處理指令與 16-bit 溢位防禦】
* **原問題**：用 `#define` 宣告常數表示 1 年有多少秒。
* **解析與解答**：
  1. **巨集語法與結尾分號**：寫法為 `#define SECONDS_PER_YEAR (60UL * 60UL * 24UL * 365UL)`。結尾**絕對不能加分號 `;`**，因巨集為純文字替換，若加分號在 `if (sec > SECONDS_PER_YEAR) ... else ...` 會在 `else` 前產生多餘分號造成語法崩潰。
  2. **16-bit 溢位與 UL 後綴**：傳統 16 位元 MCU 的 `int` 最大上限僅為 $32,767$。一年的秒數為 $31,536,000$ (超過 $2^{16}$)，無 `UL` (Unsigned Long) 告知編譯器提升為 32-bit 長整數會產生溢位負數亂碼。

### HackMD 第 2 題【標準 MIN 巨集與副作用陷阱】
* **原問題**：寫出標準的 `MIN` 巨集。
* **解析與解答**：
  1. **標準巨集寫法與全括號**：寫法為 `#define MIN(A, B) ((A) <= (B) ? (A) : (B))`。每一個參數 `A`、`B` 以及整體運算式外圍必須加滿小括號，防範純文字展開時引發的運算子優先級 (Precedence) 錯亂。
  2. **`MIN(*p++, b)` 副作用 (Side Effects)**：純文字展開後為 `((*p++) <= (b) ? (*p++) : (b))`。在三元運算子比較與條件取值時 `*p++` 被評估了 **兩次**，導致指標 `p` 意外被遞增兩次跳格。

### HackMD 第 3 題【預處理指令 #error 的妙用】
* **原問題**：`#error` 的目的與語法格式？
* **解析與解答**：
  1. **編譯階段 (Compile-time) 直接作用**：`#error` 在預處理掃描（編譯前）作用。若條件成立會吐出自訂錯誤訊息並**強制停止編譯**。
  2. **實戰檢查範例**：
     ```c
     #ifndef BOARD_VERSION
         #error "BOARD_VERSION is not defined! Halting compilation."
     #endif
     ```
     防止開發者因漏設硬體版本參數而產出錯誤 binary。
